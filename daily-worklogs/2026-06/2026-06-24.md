[gitlab-runner 설정 진도 (하단 내용에 대해 아직 진행 못함.)]
✦ 제공해주신 CI 출력 로그와 .gitlab-ci.yml 파이프라인 설정을 바탕으로
  현재 배포가 실패한 원인을 분석한 결과입니다.

  크게 두 가지 문제가 확인되며, 두 번째 문제가 파이프라인을 실패하게
  만든 결정적인 원인입니다.

  1. Docker Compose 버전/명령어 호환성 문제 (경고성)
   * 로그:

   1     [CMD] echo '***' | sudo -S docker compose version
   2     [ERR] Password: docker: 'compose' is not a docker command.
   * 원인 분석:
      배포 헬퍼 스크립트(cicd_deploy_helper.py)에서 최신 플러그인 방식인
  docker compose(v2, 띄어쓰기) 명령을 먼저 시도했으나, 접속한 배포
  서버(Synology NAS)에는 구버전인 독립형 docker-compose(v1, 붙여쓰기)만
  설치되어 있어 발생한 에러입니다. 스크립트 내부적으로 이를 감지하고
  docker-compose로 Fallback하여 다음 단계를 진행했으므로, 이 자체로
  파이프라인이 중단되진 않았습니다.

  2. IMAGE_NAME 환경 변수 누락으로 인한 Pull 실패 (핵심 원인)
   * 로그:

   1     msg="The \"IMAGE_NAME\" variable is not set. Defaulting to a
     blank string."
   2     Error response from daemon: no such image: :015fe4fa: invalid
     reference format
   3     [오류] CI/CD 배포 중 실패: 명령 실패 (exit 1)
   * 원인 분석:
       1. 원격 서버에서 docker-compose pull 명령이 실행될 때,
          docker-compose.yml 내부에 선언된
          ${IMAGE_NAME}:${DOCKER_IMAGE_TAG} 형태의 이미지를 참조하려고
          시도했습니다.
       2. 로그를 보면 DOCKER_IMAGE_TAG 변수는 이번 커밋의 Short SHA인
          015fe4fa로 정상적으로 치환되었습니다.
       3. 그러나 앞부분의 IMAGE_NAME 변수가 비어있는 문자열로 인식되면서
          최종 조합된 이미지 이름이 :015fe4fa라는 잘못된 형식(Invalid
          Reference)이 되어 도커 데몬이 이미지를 찾지 못해 다운로드에
          실패했습니다.
   * 발생 이유 추정:
      .gitlab-ci.yml 스크립트를 보면 echo
  "IMAGE_NAME=$CI_REGISTRY/aqa-portal" >> $ENV_FILE_CONTENT 명령어를
  통해 .env 파일에 변수를 추가하고 있습니다.
      하지만 GitLab 프로젝트 설정에 컨테이너 레지스트리가 비활성화되어
  있어 기본 제공되는 $CI_REGISTRY 변수 값이 비어있거나, 기존에 주입된
  원본 파일($DEV_ENV_FILE) 내에 빈 IMAGE_NAME= 값이 덮어씌워져 도커
  컴포즈가 원격 서버에서 환경 변수를 올바르게 읽어오지 못한 상태입니다.

  💡 요약
  "배포할 Docker 이미지의 경로(IMAGE_NAME)를 원격 서버의 도커 컴포즈가
  알지 못해 잘못된 주소(:015fe4fa)로 다운로드를 시도하다가 실패한
  상태"입니다. .gitlab-ci.yml의 환경변수 주입 로직이나 GitLab Variable
  설정을 점검하여 .env 파일에 유효한 IMAGE_NAME 값이 정상적으로
  기록되는지 확인이 필요합니다.
